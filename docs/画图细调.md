# 画图按模型细调（2026-11-04）

代码在 shared/src/commonMain/kotlin/com/guixing/jixunying/model/ImageTuning.kt，ImageGen 照它发参数，ImagePick 照它排先后，generate_image 的说明里照它写各家脾气。

## 起因

用户在微信里拿同一类提示词（25 岁女生、黑吊带裙、赤足坐在黑背景地上）把各家画图模型挨个测了一遍（微信对话 7bccdf64…，北京时间 11-04 15:54—16:58），然后说：「我刚刚测试了所有模型的生成图片，每个模型风格不一样，得需要写程序细调，你看看聊天记录」。

## 用户的原话（定去留的依据）

- 16:01「有两个脚抽搐的是哪个模型」→ 智谱 GLM-Image；16:02「这俩模型以后少用」（GLM-Image 和 15:54 那张 MiniMax image-01）
- 16:04「这俩还算不错 但是价格差距有点大」（千问 qwen-image-3.0-pro 0.25 元、MiniMax 15:57 那张 0.025 元）
- 16:18 可灵 kling-v3-omni「这个女生好看」；16:19「你说的对 他细节不行 但是他这张脸好看，模型不行 但是他审美挺好」
- 16:18 智谱 cogview-4「这个女生好看，但是脚都变形了」；16:19「还是毛病 审美挺好 模型太抽搐」
- 16:20 万相 wan2.7-image-pro「最丑的一个」；16:25「还有那个偏男性的脸，细节做的都挺好 就是审美不太行 可以调」；16:47（阿德又画了两张以后）「能用，行」
- 16:25「我没说明白，我的意思是，MiniMax 和千问他们的模型不会抽搐，虽然他们的审美不太行，但是审美可以调，可灵等等那些模型虽然审美行，但是抽搐模型上限不太行，所以直接放弃」
- 16:26「你说的对 但是不能只靠一个模型」；16:28「可灵放弃，太抽搐了，硬性条件没有」
- 发给我的：「如果模型实在调不过来 就不要调了，不要为了它浪费额度」；看了我测的两张 MiniMax：「第一张手抽搐了」

规矩：手脚画畸形是硬条件，不行的直接放弃；审美不行的由程序调；调不过来的别再花钱；留几家轮着用。

## 接口参数（都照官方文档）

- 分辨率（ImageTuning.targetPixels）：同样的钱画到最大。qwen-image-3.0 1K、2K 都是 0.18 元 → 按 2K 画（3:4 是 1760×2368）；qwen-image-2.0 / 2.1 一个价 → 2K；qwen-image-3.0-pro「面积不大于 2,250,000 为 qima_output_1k」0.25 元、超过 0.5 元 → 压在 1K 档里画到最大（3:4 是 1296×1728）；万相 2.7 默认就是 2K → 2K（以前按 1K 左右画，比它默认的还小）；万相 2.6 / 2.5 → 1440×1440 档。千问、万相 2.7 单边可以过 2048（官方 2K 推荐尺寸 3:4 是 1728*2368）。
- 大图存成 JPEG：PNG 超过 2 MB、不带透明的存成 JPEG 质量 92（Engine.compactImage），2K 的 PNG 四到六 MB，手机遥控时取得慢。
- 反向提示词：官方示例原文「低分辨率、低质量、肢体变形、手指变形、颜色过度饱和、蜡像感、面部细节缺失、皮肤过度光滑、AI 痕迹明显、构图混乱、文字模糊或扭曲」。千问 2.0 / 3.0、万相 2.6 放 parameters，老万相（2.5 及以前、wanx）放 input；千问 2.1、万相 2.7、z-image、可灵、Vidu 不发（文生图指南原文「qwen-image-2.1 系列、wan2.7-image-pro 和 wan2.7-image 不支持此参数，其余模型均支持」）。
- 改写开关：千问、老万相照官方默认开（「图像生成微调」原文「建议保持默认值以获得最佳效果」；qwen-image-3.0 的思考模式要开着改写才生效）；万相 2.7 不发 prompt_extend、发 thinking_mode = true（指南原文「不支持 prompt_extend，请改用 thinking_mode」）；z-image 关（API 参考原文默认 false，开了算「思考」档 0.2 元一张——以前一直开着、账上按 0.1 记）；MiniMax prompt_optimizer 只给 80 字以下的短描述开（官方默认 false；同一段描述同一个种子，开着画出来脸偏老、不像描述）。
- 两处官方说法不一样：文生图指南说「已编写详细提示词」时关掉 prompt_extend，图像生成微调说保持默认。千问这边照「保持默认」开着（开着才有思考模式），没做开关对比（未确认哪个更好）。
- MiniMax 被拦：返回里 metadata.failed_count（「因内容安全检查失败而未返回的图片数量」）大于 0 当没画成；11-04 还回过一次灰底带零星彩点的图、状态码照样成功，几乎一整张中灰的也当没画成（ImageGen.looksBlank，只认中灰，黑底白底的正常图不算）。
