# 向量和语音设计说明

写于 2026-10-12，草案。用户说「向量接口，语言接口，也加上吧」（「语言」按「语音」理解：读出来 + 听写）；用户补了一句「minimax，mimo 有语音模型」。各家接口和价格 2026-10-12 查的官方文档，原话摘在 docs/参考资料.md「向量和语音（2026-10-12）」；另一个助手已只看官方原文逐条核对（10-12），写进代码的数字以参考资料里那一节为准。

和 Code 栏无关（不涉及别人的源码），照 Code 栏的做法：写代码的 AI 照这份文档和本仓库代码做，主会话审。

## 1 用来做什么

- 向量：按意思搜。现在「搜聊天记录」「我的文档」「挑长期记忆」都是按字面找，换个说法就找不到（构想里的「记忆二期」）。有了向量：把文字切成段、算成向量存在本机，搜的时候把问题也算成向量，按相似度找最接近的几段，再和字面命中合在一起排。
- 语音：
  - 读出来：每条 AI 回答下面一个「读出来」按钮；设置里可以打开「回答完自动读」（默认关）。
  - 听写：输入框旁边一个话筒按钮，按下开始录、再按一下停，识别出来的字填进输入框（不直接发，用户看一眼再发）。
  - 微信里收到的语音消息先不管（以后再说）。

## 2 接哪几家（都用用户自己填的 Key，不另收 Key）

向量（用户在用的几家里只有智谱、千问有；DeepSeek、MiniMax、小米的官方文档里没有向量接口）：
- 智谱 embedding-3：POST {智谱接口地址}/embeddings（OpenAI 兼容写法）；单条最多 3072 token、一次最多 64 条；维度 2048 / 1024 / 512 / 256，默认 2048（我们用 1024，存得小、够用）；0.5 元 / 百万 token。
- 千问 text-embedding-v4：POST {千问接口地址}/embeddings（OpenAI 兼容）；单条最多 8192 token（同站另一页写 33000，对不上，按 8192）、一次最多 10 条；维度默认 1024；价格页是动态加载的，没读到（记账先算「价格未知」）。
- 「自定义」：任何 OpenAI 兼容 /embeddings 接口（硅基流动、本机 Ollama 等），模型名用户填。
- 没有能用的向量模型时：按意思搜这个开关灰掉，说明为什么，照旧按字面搜。

读出来（TTS）：
- 小米 mimo-v2.5-tts：走 {小米接口地址}/chat/completions，user 消息可放说话风格，assistant 消息放要读的字；audio.voice 可选 mimo_default（默认）、冰糖、茉莉、苏打、白桦、Mia、Chloe、Milo、Dean；audio.format 用 wav；返回 base64（官方页面没直接写所在路径，按 choices[0].message.audio.data 写并用真 Key 实测确认）。官方写「限时免费」。默认先挑它。
- MiniMax speech-2.8-turbo / speech-2.8-hd：POST {MiniMax 接口地址去掉 /v1}/v1/t2a_v2；text 小于 1 万字符；voice_setting.voice_id（例如 male-qn-qingse）、speed 0.5～2；audio_setting.format 用 wav；返回 data.audio 是十六进制编码；base_resp.status_code 0 才算成功。turbo 2 元 / 万字符、hd 3.5 元 / 万字符，1 个汉字算 2 个字符。
- 智谱 glm-tts：POST {智谱接口地址}/audio/speech；一次最多 1024 字；voice 有 tongtong（默认）、chuichui、xiaochen 等；response_format 要显式给 wav（不给默认是 pcm）；官方建议采样率 24000；返回二进制音频。2 元 / 万字符。
- 千问 qwen3-tts-flash：POST {千问域名}/api/v1/services/aigc/multimodal-generation/generation（不是 OpenAI 兼容）；一次 512 token / 600 字以内；返回 output.audio.url（24 小时有效，要再下载）。价格没查到（未确认）；用户千问余额很少（CLAUDE.md 红线），自动挑的时候排最后。

听写（ASR）：
- 小米 mimo-v2.5-asr：走 {小米接口地址}/chat/completions，音频 base64（data URL）放在 user 消息的 input_audio 里；只认 mp3、wav；language auto / zh / en；字在 choices[0].message.content。0.5 元 / 小时（按秒算）。默认先挑它。
- MiniMax asr-1.0：POST {MiniMax 接口地址去掉 /v1}/v1/speech_to_text，multipart/form-data；一段最长 500 秒、50 MB；2.5 元 / 小时。
- 智谱 glm-asr-2512：POST {智谱接口地址}/audio/transcriptions，multipart；只认 wav、mp3；一段最长 30 秒、25 MB（长的要切成 25 秒一段分开识别再拼）。16 元 / 百万 token（约 0.0002 元 / 秒）。
- 千问 qwen3-asr-flash：官方写「HTTP（OpenAI 兼容）」，但那页 API 参考打开是 404，没查清怎么调，第一期不接。

## 3 设置

设置里加一页「语音」：
- 读出来用哪个（自动挑 / 指定服务商和模型）、音色（按所选模型给可选列表；MiniMax 的音色可以手填编号）、语速；「回答完自动读」开关（默认关）；「试听」按钮。
- 听写用哪个（自动挑 / 指定）。
- 说明一句：读出来、听写都会把文字或录音发给所选的服务商。

设置里加一页「按意思搜」（或者放进「记忆」页，写代码的时候看哪种更顺，问主会话）：
- 开关（默认关）；向量模型（自动挑 / 指定）；打开前先估算：现有文档和聊天记录大约多少字、算一遍大约多少钱（按价格表），用户点了才开始算。
- 进度（算了多少段 / 总共多少段）、「重新算一遍」（换了模型必须重算，维度不一样不能混用）。
- 新聊天、新文档进来以后在后台慢慢补算；出错照「后台出错提示」那一套记下来，不悄悄停。

自动挑的顺序：读出来 小米 → MiniMax turbo → 智谱 → 千问；听写 小米 → MiniMax → 智谱；向量 智谱 → 千问 → 自定义。只挑已启用、填了 Key 的服务商。

## 4 记账

- 读出来按字数记，听写按秒记，向量按 token 记；UsageRecord 用新的 kind：tts / asr / embed，花费页按用途分开显示。
- 价格表（Prices.kt）要能表示「每万字符多少钱」「每小时多少钱」：在 ModelPrice 里加按字符、按秒的价格（照现有 perImage 那样），Prices.cost 按 kind 算。官方写「限时免费」的先记 0，并在说明里写「限时免费，以后可能收费」。

## 5 各端怎么放声音、怎么录音

- 统一要 wav（16 位 PCM），电脑上用 Java 自带的 javax.sound 就能放；录音也用 javax.sound（16 kHz、单声道、16 位），存成 wav。
- 手机上：放用 MediaPlayer（写成临时文件再放）；录音用 AudioRecord，要 RECORD_AUDIO 权限（第一次点话筒时问，拒绝了就提示去系统设置开）。
- 读长回答：先去掉 Markdown 记号和代码块，按句号切成段（每段不超过所选模型的上限），一段一段合成、一段一段放；点「停止」就不再往下合成。
  - 实现（10-12 主会话审第 1 张单时加的）：界面先发 SpeakPlan(text)，引擎不联网、只返回挑中的服务商 / 模型和切好的段（SpeechPlan）；界面再对每一段发 Speak(段, providerId, modelId, prepared = true)，放这段的同时可以先合成下一段；点「停止」就不再发。prepared 的段引擎不再清理一遍。
  - 设置里的音色只给设置里选的那家用；那家用不了、自动换到别家时用别家的默认音色。
  - 各家实测的 wav：MiniMax 32000 Hz，智谱、小米 24000 Hz，都是单声道 16 位（10-12 真 Key）。采样率不一样，所以不拼成一个文件，一段一段放。
  - 段的大小（10-12 模拟器实测后定）：第一段 60 字以内（一两句，先开口），后面每段最多 300 字（也不超过各家上限）；在句子之间换段。按各家上限（小米 1000 字）切时，第一段要等十几秒、手机 Java 堆满。
- 听写之前程序先看音量：整段最大振幅不到满幅的约 1.2%（-38 dBFS）就当没录到声音，提示用户、不发给服务商（听写模型对着静音会编出一句话来，10-12 模拟器实测）。
- 设置里自动挑的时候不给选音色（用各家默认）；指定了一家才能选音色、模型；不认语速的那家（小米、千问）不显示语速滑块。
- 手机遥控电脑时：读出来、听写都用手机本机的引擎和 Key（手机配对时已经把服务商同步过来），不经中转传音频；手机本机没有能用的服务商时才提示。

## 6 分工（写代码的 AI 照这个顺序一张单一张单做）

1. 语音引擎：各家协议的适配（小米、MiniMax、智谱、千问 TTS）、Settings.speech、指令 Speak / Transcribe、记账和价格单位，测试用假服务器把四家的请求格式和返回解析都测到（教训 64：自己拼的格式要对着官方原文核）。
2. 语音界面：电脑和手机的放音、录音（Platform 加接口），回答下面「读出来」、输入框的话筒、设置页「语音」，截图测试。
3. 向量引擎：/embeddings 客户端、切段、本机向量库（存成文件，暴力算相似度就够）、文档和聊天记录的增量补算、search_documents / search_history 按意思和按字面合并排序、记账，测试。
4. 向量界面：设置开关、估算、进度、重算，截图测试。

## 7 已定（用户 2026-10-12：「都可以，就一点为什么不做手机端」）

1. 「按意思搜」默认关；打开前给估算（聊天记录、我的文档分开列字数和钱），用户确认才开始算；可以只开聊天记录的。
2. 两端都做：向量的引擎代码放 jvmShared，电脑、手机各自算各自本机的聊天和文档，各自开关、默认关（CLAUDE.md「两端都能单独用」：手机单独用时聊天只存在手机上）。手机遥控电脑时搜的是电脑上的数据，用电脑的结果。手机端要在模拟器上点一遍（教训 32）。
3. 千问的听写第一期不接（API 参考 404、价格没读到）。
