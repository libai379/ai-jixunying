# 构想

写于 2026-09-30。还没动手，这里记录方向和理由，动手前可以再改。

## 一、为什么要做（问题）

一群 AI 自由讨论，通常不会出结果：大家附和其中一个，然后一起被带偏。这不是感觉，研究测出来了：

- 7 个不同模型对 600 道题投票，讨论一轮后全票一致从 39.5% 涨到 95.2%，准确率只从 91.8% 到 92.4%；"一致地错"从 8 道涨到 22 道。讨论抹掉了分歧信号，却没提高正确率。
- 模型经常因为同伴的说法，把对的答案改成错的；讨论越久准确率越低。
- 85.5% 的情况下模型直接照搬多数答案；团队里有人答对了，投票时也会被扔掉（最多差 32.3 个百分点）。
- 成员越多越好，但投票前讨论轮数越多越差。
- 同一种模型自己跟自己辩论效果最差；不同厂商的模型混在一起更好。

所以只做娱乐意义不大。AI集训营的价值在于：**把多家模型的独立意见和分歧摆出来，并且能量化谁被带偏了。**

## 二、会审模式（核心机制）

参考 Karpathy 的 llm-council，再加上研究里验证过的几条：

1. 独立作答：每个模型先各答各的，互相看不到。
2. 匿名互评：答案去掉名字、打乱顺序，每个模型给别人挑错、排名。
3. 主席汇总：一个模型汇总成最终答案，必须写出分歧和少数派意见，不能只写共识。
4. 只讨论一轮就投票，不无限聊。
5. 显示首轮分歧度：一开始就意见不一的，比讨论完的"一致"更有信息量。
6. 用不同厂商的模型（手上有九家国产模型，天然优势）。
7. 能验证就验证：代码题直接跑，比互相说服可靠。

## 三、狼人杀集训场（最重要）

狼人杀不是玩的。它是唯一有标准答案的场景：谁是狼是确定的，所以"被带偏""识破谎言""少数派坚持对了"都能精确计算。狼人本身就在利用附和，天然是抗从众、抗欺骗的训练场。

### 前身里已发现的问题（G:\ai-discussion-app\src\wolf）

- 投票是轮流投的，每人的投票理由写进发言记录，后面的人看得到 → 看着前面的票跟票。这是"渐渐带偏"的直接原因之一。
- 没有"独立判断"这一步，事后分不清是自己想的还是跟风。
- 投票解析失败时随机替它投一个人（actions.js wolfAIVote 末尾）→ 测评数据会失真。

### 要加的机制

1. 私下判断：每天发言开始前、投票前，每个 AI 各写一次"怀疑谁、几成把握、理由"，只记录不公开。
2. 同时投票：所有人同时交票，最后一起公布。
3. 警长当主席：汇总时必须列出少数派意见。
4. 解析失败就重问或记弃权，绝不随机代投。

### 每局自动算的指标

- 被带偏率：私下判断是对的，最终却跟着多数投错
- 识狼准确率：私下判断里对狼的命中
- 骗票成功率（狼方）：好人投给好人的票里，有多少是狼带的节奏
- 少数派正确率：投了少数票且投对的比例
- 首轮分歧度
- 每次调用的 token、耗时、花费

### 对照实验

同样的角色配置，开会审机制 vs 不开，各跑若干局，比好人胜率和被带偏率。先证明机制有用，再搬进日常会审模式。

- B. 训练：调出一套会配合、不被带偏的 AI 阵容和提示词。

## 四、记忆系统（综合四家的做法）

参考 Claude Code、Cursor、MiMo Code、WorkBuddy 的上下文管理：

1. 三级压缩（Claude Code）：零成本清理（删 PASS、系统提示、截短长发言）→ 结构化摘要（话题 / 已定结论 / 分歧 / 待办 / 各成员立场 / 主持人要求）→ 合并时"主持人要求"和"已定结论"只增不删。
2. 主持人原话逐字保留（Claude Code）。
3. 共享记录员（MiMo）：全群一个记录员压缩，大家共用；每个成员只额外记一行"我的立场"。
4. 旧聊天存档可检索（Cursor / MiMo）：压缩掉的原文存档，按关键词捞几条相关的带上。缺点：不是语义检索，换个说法可能搜不到。
5. 跨会话长期档案（WorkBuddy）：关于主持人的偏好、规矩，清空聊天也不丢，可查看可手改。
6. 定期整理（MiMo 的 /dream）：攒够量自动去重合并。

记录员默认模型：mimo-v2.6-flash（编程测评里指令遵循 5.0、全程只花 0.14 元、缓存命中便宜 120 倍）。备选 MiniMax-M3（简洁度最高，但"爱多做一步"，可能添油加醋）。不用 GLM 系列（指令遵循最低，且会自信地下错误结论）。注意：那次测评测的是写代码，不是中文摘要，要用"同一段聊天分别压一次对比"来实测。

## 五、技术路线

- 只做 Windows 桌面版，不做网页版。
- 推荐：Kotlin Multiplatform + Compose Multiplatform。
  - 理由：癸星是 Kotlin + Jetpack Compose（Kotlin 2.4.0、Compose 1.11.2），它的 selector 模块本来就是 Kotlin 多平台。引擎写成纯 Kotlin 的 :core 模块，Windows 界面用 Compose Desktop，将来并入癸星时 :core 原样复用，界面代码大部分也能搬。
  - 癸星的液态玻璃风格（TunedGlassParams）将来可以在桌面版上沿用。
- 备选（不推荐）：Electron / Tauri 可以直接复用前身的 JS 代码，但将来并入癸星要整个重写。
- 批量跑对局：桌面版自带"无人值守批量跑"，对照实验要几十局，手动跑不现实。
- 统一的模型调用层：前身有三处重复的请求代码（chat.js、wolf/actions.js、memory.js），新项目只留一处，统一处理 OpenAI 兼容 / Claude 格式、流式、temperature 兼容（见教训库）、token 统计。
