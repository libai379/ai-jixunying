# 教训库

每条：发生了什么 → 下次怎么做。

## 模型接口

1. **不同模型对参数的限制不同，别写死。** kimi-k3 只接受 temperature=1，写死 0.9 直接 400。
   → temperature 做成每个模型可配，留空时不传（用模型默认值）；遇到参数类 400 自动去掉该参数重试，并记住这个模型。
2. **错误重试不能原样重发。** 前身第一次失败后改用流式重试，但出错的 temperature 还在，重试必然再失败，用户看到的是第二次的报错，误导排查。
   → 重试前先看错误内容，针对性修改请求。

## 多智能体讨论

3. **自由讨论会让模型互相附和、一起跑偏。** 研究数据见 构想.md 第一节。
   → 先独立作答再交流；匿名；少讨论、早投票；汇总必须保留少数派。
4. **"大家都同意"不代表对。** 讨论后一致率暴涨，准确率几乎不变，错误反而变成了一致的错误。
   → 看首轮分歧度，不把讨论后的一致当作可靠证据。
5. **轮流投票 + 公开理由 = 跟票。**
   → 同时投票，最后统一公布。
6. **测评数据不能有"兜底随机值"。** 前身投票解析失败会随机代投，平时无所谓，测评时会污染数据。
   → 解析失败就重问，再失败记弃权，并在日志里标出来。

## 记忆

7. **追加记录时用"最近 N 条"会重复。** 前身每次发言都把最近 5 条再写一遍。
   → 按消息 id 增量追加，写入前去重。
8. **每个成员各自总结同一段聊天是浪费。**
   → 全群一个记录员，结果共享。

## 选模型

9. **编程测评分数不能直接当别的任务的分数。** 选记录员参考了编程测评的"指令遵循""简洁"，但摘要能力没测过。
   → 用同一段真实聊天实测对比后再定。
10. **花费数字被缓存价格扭曲。**（来自九模型测评）只有元、没有 token 明细的花费不能外推。
    → 调用层记录 token 明细（命中缓存 / 未命中 / 输出）。

## 工程

11. **Android / Gradle 工具链怕非 ASCII 路径。**
    → 工程目录用 ai-jixunying，中文名只用于显示。
12. **改 appId 等于换一个 App，用户数据全丢。**
    → 前身 appId 和 localStorage key 永远不动；新项目一开始就定好包名，之后不改。

## 2026-10-07 第一版开发

13. **Bash 工具会吃反斜杠。** 用 heredoc + python 改 Kotlin 正则，`\b`、`\1` 被折成退格符和 0x01 控制字符，编译不报错，正则静默失效。
    → 含转义的代码一律用 Write / Edit 写；改完扫一遍源码里有没有控制字符。
14. **Ktor 的 Application 扩展函数里，名叫 engine 的字段会被 Application.engine 抢走。** LanServer 的构造参数叫 engine，路由里全解析错了。
    → 别给字段起 engine、application、call 这类和框架成员同名的名字。
15. **事件走 SharedFlow 收集，回执走另一条路，两者在线路上会乱序。** 手机发「新建对话」，回执先到、新对话的状态后到，界面拿着 id 找不到对话。
    → 引擎用同步监听器推事件，事件先进发送队列，回执后进。
16. **CMP 1.12 带的 material3 要求 compileSdk 37。** compileSdk 36 时 checkDebugAarMetadata 直接失败。
    → compileSdk 37（targetSdk 可以不动）。
17. **Android Studio 自带的 jbr 没有 jpackage，打不了 Windows 安装包。**
    → gradle.properties 的 packageJdk 指向完整 JDK（F:/JDK）。jlink 模块用 :desktopApp:suggestRuntimeModules 查，另外手动加 jdk.charsets（GBK 文本解码要用）。
18. **免费必应搜索能用，但读网页正文时取第一个 article / main 容易取到边栏。**
    → 在候选块里挑文字最多的，太短就用整页。
