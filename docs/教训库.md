# 教训库

每条：发生了什么 → 下次怎么做。

## 模型接口

1. **不同模型对参数的限制不同，别写死。** kimi-k3 只接受 temperature=1，写死 0.9 直接 400。
   → temperature 做成每个模型可配，留空时不传（用模型默认值）；遇到参数类 400 自动去掉该参数重试，并记住这个模型。
2. **错误重试不能原样重发。** 前身第一次失败后改用流式重试，但出错的 temperature 还在，重试必然再失败，用户看到的是第二次的报错，误导排查。
   → 重试前先看错误内容，针对性修改请求。

## 多智能体讨论

3. **自由讨论会让模型互相附和、一起跑偏。** 研究数据见 构想.md 第一节。
   → 先独立作答再交流；匿名；少讨论、早投票；汇总必须保留少数派。
4. **"大家都同意"不代表对。** 讨论后一致率暴涨，准确率几乎不变，错误反而变成了一致的错误。
   → 看首轮分歧度，不把讨论后的一致当作可靠证据。
5. **轮流投票 + 公开理由 = 跟票。**
   → 同时投票，最后统一公布。
6. **测评数据不能有"兜底随机值"。** 前身投票解析失败会随机代投，平时无所谓，测评时会污染数据。
   → 解析失败就重问，再失败记弃权，并在日志里标出来。

## 记忆

7. **追加记录时用"最近 N 条"会重复。** 前身每次发言都把最近 5 条再写一遍。
   → 按消息 id 增量追加，写入前去重。
8. **每个成员各自总结同一段聊天是浪费。**
   → 全群一个记录员，结果共享。

## 选模型

9. **编程测评分数不能直接当别的任务的分数。** 选记录员参考了编程测评的"指令遵循""简洁"，但摘要能力没测过。
   → 用同一段真实聊天实测对比后再定。
10. **花费数字被缓存价格扭曲。**（来自九模型测评）只有元、没有 token 明细的花费不能外推。
    → 调用层记录 token 明细（命中缓存 / 未命中 / 输出）。

## 工程

11. **Android / Gradle 工具链怕非 ASCII 路径。**
    → 工程目录用 ai-jixunying，中文名只用于显示。
12. **改 appId 等于换一个 App，用户数据全丢。**
    → 前身 appId 和 localStorage key 永远不动；新项目一开始就定好包名，之后不改。

## 2026-10-07 第一版开发

13. **Bash 工具会吃反斜杠。** 用 heredoc + python 改 Kotlin 正则，`\b`、`\1` 被折成退格符和 0x01 控制字符，编译不报错，正则静默失效。
    → 含转义的代码一律用 Write / Edit 写；改完扫一遍源码里有没有控制字符。
14. **Ktor 的 Application 扩展函数里，名叫 engine 的字段会被 Application.engine 抢走。** LanServer 的构造参数叫 engine，路由里全解析错了。
    → 别给字段起 engine、application、call 这类和框架成员同名的名字。
15. **事件走 SharedFlow 收集，回执走另一条路，两者在线路上会乱序。** 手机发「新建对话」，回执先到、新对话的状态后到，界面拿着 id 找不到对话。
    → 引擎用同步监听器推事件，事件先进发送队列，回执后进。
16. **CMP 1.12 带的 material3 要求 compileSdk 37。** compileSdk 36 时 checkDebugAarMetadata 直接失败。
    → compileSdk 37（targetSdk 可以不动）。
17. **Android Studio 自带的 jbr 没有 jpackage，打不了 Windows 安装包。**
    → gradle.properties 的 packageJdk 指向完整 JDK（F:/JDK）。jlink 模块用 :desktopApp:suggestRuntimeModules 查，另外手动加 jdk.charsets（GBK 文本解码要用）。
18. **免费必应搜索能用，但读网页正文时取第一个 article / main 容易取到边栏。**
    → 在候选块里挑文字最多的，太短就用整页。

## 2026-10-07 第二轮

19. **把「不需要服务器」理解成了「只能局域网」。** 用户说「桌面端就是移动端的服务器」，参照物是 WorkBuddy：人在外面用手机指挥家里的电脑。只能局域网用，等于人在电脑旁边，用户说这没有意义。
    → 用户拿某个产品当参照时，先查清那个产品具体怎么做（这次是 WorkBuddy 的手机连接电脑、微信 Claw），再定方案。
20. **「不要服务器」不等于没有任何中转。** 两台在不同网络里的设备，总得有个中间人牵线；WorkBuddy 也是走腾讯的服务器。
    → 借用现成的免费公共中转（MQTT），内容端到端加密，用户不用自己搭、不用花钱。要跟用户说清楚数据会经过第三方服务器，但对方只看得到乱码。
21. **公共中转的地址会变，长连接会变「僵尸」。** broker-cn.emqx.io 现在解析到 AWS 爱尔兰，已经不在上海。桌面开发版挂了一阵后，显示「已连上 2/2」却收不到手机的配对请求；新开的进程用同样的数据马上就能配对。
    → 每个连接定时往自己订阅的探测主题发消息，收不到就拆掉重连（重新解析域名）；同时连几家不同公司的中转（EMQX + HiveMQ）。不要只看「连接状态」。
22. **Paho 的自动重连只在第一次连上之后才生效。** 第一次就连不上时它不会自己重试。
    → 第一次连接自己写重试循环。
23. **一次性配对码的「补发宽限」差点变成漏洞。** 为了让手机补发的配对请求能收到回复，旧二维码保留了 3 分钟，结果别的手机在这 3 分钟里也能用旧码配对。是自动测试抓出来的。
    → 宽限只对刚用这个码配对成功的那台手机（设备号和密钥都对得上）有效，其他一律拒绝。
24. **EMQX 两个公共入口（broker-cn 和 broker）其实连着同一个集群。** 每条消息会从两个连接各收到一份。
    → 发的时候给消息编号，收的时候按编号去重；切片也要能乱序拼。
25. **不要去翻别的软件的设置文件找 Key。** 读 WorkBuddy 的模型清单（Key 打码）可以，再往下读它的设置文件被系统拦了。
    → 需要用户的 Key 就让用户自己在 App 里填，或者做成用户主动点的「导入」功能并先问用户。
26. **Windows 上默认的 DirectX 渲染会让字闪。** 用户在自己电脑上看到：打字、鼠标移过、打开弹窗或切换页面时字都在闪。我用截图逐帧对比没抓到（采样间隔比闪烁长），是用户说清楚场景后才定位。这是 Compose 桌面版的已知问题（JetBrains/compose-multiplatform#553）。
    → Main.kt 启动时默认把 skiko.renderApi 设成 OPENGL（用户另外指定的除外）。以后别拿「我截图没看到」否定用户看到的现象。
27. **输入框边打边截断长度，和拼音输入法打架。** 名字框写成 it.take(12)，拼音字母也算长度，打到一半被截，输入框会乱跳。
    → 输入时不截，保存时再截。
28. **给用户打开桌面版别直接运行 build 目录里的程序。** 运行中的程序占住文件，之后 createDistributable 删不掉目录、打包失败，只能先把用户正在用的窗口关掉。
    → 先复制到 G:\DevCache\ai-jixunying-app 再从那里运行。
29. **用户正在用的窗口，别去动他的鼠标。** 为了找闪烁，我用脚本在用户屏幕上移动鼠标，结果打扰了用户正在填的「添加成员」弹窗。
    → 只截图，不模拟输入；要复现就开一个单独的开发版窗口，并先告诉用户。
